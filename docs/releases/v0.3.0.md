# v0.3.0 — Control Center: the two-plane app

kissrobert.com becomes a **two-plane system**: the public studio homepage plus a
private, authenticated **`/admin`** operations console — the operator's single
source of truth for status, cycles, and health across the whole fleet.

## Highlights

- **Two-plane architecture.** The public site stays static, stateless, and
  zero-JS; a new private plane (`/admin` + `/api/*`) is server-rendered on Vercel
  and backed by a database. One codebase, two clearly separated planes.
- **Control Center (`/admin`).** A collapsible-sidebar console with an
  **Overview / Unified Ops View** — one live status line per project (status,
  version, last-shipped, current cycle + progress, done/upcoming), plus
  **Notes**, **Marketing**, and **Uptime** pages.
- **Real uptime + honest status badge.** Hosted apps are pinged on a schedule;
  the `/admin/uptime` page shows response times, 90-day uptime, and an incident
  log. The homepage hero badge is now wired to that real signal — green only when
  checks actually pass, amber/red otherwise (no invented "all systems online").
- **Server connectors + snapshots.** `github.ts` ops data is captured into the
  database on a schedule, so the Overview reads **snapshot-first** (fast, and it
  survives a GitHub outage or rate limit) with a live fetch as fallback.

## Under the hood

- **Migrated hosting to Vercel** via the `@astrojs/vercel` adapter, and
  **retired GitHub Pages**. Public pages prerender; private routes opt into SSR
  per-route (`prerender = false`).
- **Supabase Postgres** is the control-center datastore, with **row-level
  security deny-by-default** — only the server (service-role key) can read or
  write. Schema lands as ordered `supabase/migrations/`.
- **GitHub OAuth gate.** `/admin` is locked to a single-operator allowlist via
  Supabase Auth; the middleware fails closed to the login page.
- **Scheduled work runs on GitHub Actions** hitting secret-protected cron
  endpoints (`/api/cron/ping`, `/api/cron/snapshot`) — not Vercel Cron, which
  would need a paid plan for sub-daily runs.

## Security baseline

- **Audit log.** Every control action (notes/marketing/seo writes, plus sign-in,
  sign-out, and denied logins) is recorded with the operator identity.
- **HTTP security headers** on every response — HSTS, `nosniff`, `X-Frame-Options`
  / CSP `frame-ancestors 'none'`, and locked-down referrer / permissions policies.
- **No secrets in the client bundle.** All tokens and keys are server-only,
  non-`PUBLIC_` env vars; the public plane ships zero secrets.
