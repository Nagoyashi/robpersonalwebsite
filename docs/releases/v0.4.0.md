# v0.4.0 — Control Center: the cockpit gets a brain

The control center stops being a passive viewer and starts *telling you things*.
This cycle adds an AI layer over the fleet — a daily "state of the fleet" brief,
a semantic ops memory, and instant-refresh webhooks — and brings the whole
private-plane cron layer online.

## Highlights

- **AI fleet-digest.** A daily job gathers real signals (GitHub ops snapshots,
  uptime + incidents, marketing/notes, ops-memory hits) and has Claude
  synthesize a short brief + highlights, stored and shown at `/admin/digest`.
  Grounded in real data only — it flags what's missing rather than inventing it.
- **Ops memory on `pgvector`.** A semantic store (Supabase `pgvector`, no
  separate vector DB) the digest can recall — seeded first by uptime incidents.
- **Instant ops snapshots.** A GitHub webhook (`/api/webhooks/github`,
  HMAC-verified) refreshes a project's ops row the moment it ships, alongside the
  hourly snapshotter.
- **Cheaper by default.** The digest runs on `claude-haiku-4-5` (≈1/5 the Opus
  cost for this light summarization), overridable per-deploy via `DIGEST_MODEL`.
- **Fleet trimmed to four.** SpreadsheetMillionaire, SabeValor, Cutecumber, and
  Pandavo (VOUND folded into Pandavo; json2viz and Autory retired).

## Under the hood

- **ADR-015** defines the AI layer: GitHub-Action cron → secret-protected
  `/api/cron/*` endpoints (consistent with ADR-013, not Vercel Cron), the Claude
  API server-side only (key never in the client bundle), and `pgvector` for
  memory (embeddings via Voyage).
- **The cron/private plane is now actually running.** The uptime pinger and ops
  snapshotter — dormant since Phase 3 due to missing `CRON_SECRET`/`CTRL_PING_URL`
  and an apex→www redirect that silently no-op'd the workflows — are live and
  writing real production data, along with the new digest.
- Two new migrations (`ops_memory`, `digests`), deny-by-default RLS as ever.
